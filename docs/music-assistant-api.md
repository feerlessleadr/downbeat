# Music Assistant API and existing apps: research notes

Researched 2026-11-26 by a research subagent reading GitHub source and docs. **Verified** = read in source or docs. **Inferred** = reading between the lines. Nothing here has been tried against a real server yet. Server stable at research time: 2.10.13 (2026-11-21). Dev branch constants: `API_SCHEMA_VERSION=126`, `MIN_SCHEMA_VERSION=28`. The schema number for stable 2.10.13 was not found.

## 1. The official app (feature reference)
Repo: https://github.com/music-assistant/mobile-app (Apache-2.0). The older `kmp-client-app` looks like its predecessor (unverified).

- Kotlin Multiplatform + Compose Multiplatform, Android 9+ and iOS. Android 0.18.0 released 2026-11-25 (verified). Modules include `sendspin-kmp`, a separate Sendspin client library.
- Navigation: bottom bar Menu, Discover, Search, selected-player button. Side menu: Explore (Discover, Search, Browse), Library (Artists, Albums, Tracks, Playlists, Audiobooks, Podcasts, Radio, Genres, AI Radio), System (Party, Settings).
- The phone is also a player (Sendspin over WebRTC/WebSocket), with notification and Android Auto support. Out of v1 for Downbeat.
- Auth options: username/password, long-lived token, Home Assistant OAuth.
- **Player selection flow (docs `players-pager.md`)**: swipe a pager between players and groups; tap the name for a list; a group icon opens a sheet with a checkbox per player; "Transfer queue" is in the overflow menu. Permanent groups cannot be created in the app.
- **Why it feels convoluted (partly inferred)**: the user must juggle "selected player" vs "queue that is playing", three group kinds (temporary sync, permanent, universal), member management in a separate sheet, queue transfer as a separate action from grouping, and the phone being both remote and speaker. Release notes 0.15 to 0.18 show the selector reworked repeatedly.
- Worth copying: swipe between rooms. Everything else about the concept exposure should go.

## 2. Server API
Docs: https://music-assistant.io. The server also serves generated docs at `/api-docs` (`commands.json`, `schemas.json`, `openapi.json`, `swagger`). Use these on the real server as the source of truth for field names.

- **HTTP (verified, dev branch `webserver/controller.py`)**: `GET /info` (version, schema version, onboarding state, CORS *), `GET /ws` (websocket), `POST /api` (`{command, args}`), auth routes `POST /auth/login`, `/auth/logout`, `GET /auth/me`, `/auth/providers`, plus `/setup` and `/sendspin`.
- **Handshake (verified)**: server sends server-info first (error 503 `setup_required` if no user exists). Client sends `{"command":"auth","message_id":N,"args":{"token":"..."}}`; success returns `authenticated: true` and a `user`. Events then flow with no subscribe command.
- **Auth (verified)**: required from schema 28. `POST /auth/login` takes `provider_id` (default `builtin`), `credentials`, optional `device_name`, returns token + user. Tokens are stored hashed with a device name. A long-lived token is created via the client library (`auth.create_token()`) or the web UI. Token lifetime not found. Scopes exist; a missing scope gives 403. Plan: sign in once with username/password, then create and store a long-lived token (Android Keystore-backed storage); never store the password.
- **Messages (verified)**: request `command`, `message_id`, `args`. Success `message_id`, `result` (large results come as `partial=true` batches of 500). Error `message_id`, `error_code`, message. Event `event`, `object_id`, `data`. Exact serialized field names are in the models package, not yet read.
- **Players**: `players/all` (inferred from the client library), `players/cmd/play|pause|play_pause|stop|next|previous|seek|shuffle|repeat`, grouping `players/cmd/set_members` (target_player, player_ids_to_add, player_ids_to_remove), `group`, `ungroup`, `ungroup_many`; admin `create_group_player`, `remove_group_player`. `volume_set` and `power` exist (not read).
- **Queues**: `player_queues/all|get|items(queue_id, limit, offset)|get_active_queue(player_id)`; control `play|pause|next|previous|seek|play_index|resume`; edit `play_media(queue_id, media, option, radio_mode, start_item)`, `move_item`, `move_item_end`, `delete_item`, `clear`, `transfer(source_queue_id, target_queue_id)`; modes `shuffle|repeat|autoplay|crossfade`. `QueueOption`: play, replace, next, replace_next, add.
- **Music**: `music/search(search_query, media_types, limit, providers)`, `music/browse(path, limit, offset, sort)`, `music/recently_played_items`, `music/item_by_uri`, `music/favorites/*`, `music/in_progress_items`, `music/recently_added_tracks`. Library list commands are probably `music/artists/library_items`, `music/albums/library_items` etc. (inferred, confirm via `commands.json`).
- **Images**: ids resolve to `/imageproxy/...` paths (parameters not seen).
- **Events (verified list)**: `player_added|updated|removed`, `queue_added|updated|items_updated|time_updated`, `media_item_*`, `favorite_updated`, `providers_updated`, `core_state_updated`.
- **Reference code (Apache-2.0)**: https://github.com/music-assistant/client (Python client) and https://github.com/music-assistant/models (dataclasses, enums). Read these for exact shapes. Downbeat will need its own small Kotlin client (OkHttp websocket + kotlinx.serialization); no Kotlin library was found.

## 4. Speaker and group model
Source: `music_assistant_models/player.py` and https://www.music-assistant.io/faq/groups/ (verified).

- **Player fields a UI needs**: `player_id`, `name`, `available`, `powered`, `playback_state` (idle|paused|playing), `volume_level`, `volume_muted`, `current_media`, `group_members` (for sync groups includes the player itself), `static_group_members` (cannot be ungrouped), `can_group_with`, `synced_to` (leader id when a follower), `active_group`, `active_source`, `type`, `hide_in_ui`, `private`, `enabled`, `group_volume`.
- **PlayerType**: player, group, stereo_pair, multi_channel, protocol, display, visualizer, light, source, controller. Show only player, group, stereo_pair, multi_channel; drop `hide_in_ui`, `private`, disabled (inferred).
- **Group kinds**: temporary dynamic sync (leader holds the queue; leader off stops followers), permanent sync group (static, optional dynamic members), universal group (mixed devices, not in sync, cannot contain other groups).
- **Behaviors that matter**: `set_members` powers on added members. Removing the leader of an ad-hoc group moves the queue to a new leader. `play_media` to a grouped player releases it from the group by default (`play_media_overrides_group`, default on), otherwise redirects to the leader. A queue id equals its player id. For a follower, find what is playing via `get_active_queue(player_id)` / `synced_to` / `active_group`, never the follower's own queue. A powered group blocks playing to one of its members.

## 5. Implication for Downbeat's design (proposal, needs owner approval)
Hide players/queues/group kinds. Show one list of **rooms** (players and groups), each with state, a now-playing line and a volume slider. Tapping play on anything chooses where: the app asks "Play where?" only when it is ambiguous, defaulting to the last-used room. Grouping is one multi-select, "Also play in...", that maps to `set_members` on the target. The effective queue is resolved behind the scenes. Open design question: how to treat permanent and universal groups (just show them as rooms).

## 6. Verified against the owner's server (2026-11-26)
Unauthenticated probe of `/info`, `/auth/providers`, `/api-docs/commands.json` (311 commands), `/api-docs/schemas.json` (128 schemas), `/api-docs/openapi.json`. Authenticated calls are NOT verified yet: `tools/Sample-MusicAssistant.ps1` does that and the owner runs it.

- **Server**: 2.10.13, schema 65, min supported 28, runs as a Home Assistant add-on. Providers: `builtin` (username/password) and `homeassistant` (needs a redirect). `/info` leaks the server's LAN IP in `base_url`: never copy samples unredacted.
- **Auth**: `auth/login(username, password, provider_id, device_name)` over the websocket. Sessions: short-lived tokens that slide 30 days. `auth/token/create(name)` makes a **long-lived token, expires after 1 year, no auto-renew** (so the app must handle expiry by asking to sign in again). `AuthToken` has `expires_at`, `is_long_lived`. `auth/me`, `auth/tokens`, `auth/token/revoke` exist.
- **Corrections to section 2/4**: `PlayerType` here is `player, stereo_pair, group, protocol, display, visualizer, light, source, unknown` (no `multi_channel`). `PlayerFeature` includes `power, volume_set, volume_mute, pause, set_members, seek, next_previous, select_source, play_media, enqueue...`: gate every button on `supported_features`.
- **Exact parameters** (names verified): `players/all(return_unavailable, return_disabled, provider_filter, return_protocol_players)`; `players/cmd/set_members(target_player, player_ids_to_add, player_ids_to_remove)`; `players/cmd/volume_set(player_id, volume_level:int)`; `players/cmd/group_volume(player_id, volume_level)`; `players/cmd/power(player_id, powered)`; `players/cmd/play_pause(player_id)`; `players/cmd/seek(player_id, position)`; `player_queues/play_media(queue_id, media, option, radio_mode, start_item, sort_by, start_from_beginning, shuffle, user)` where `media` is a URI string, an item, or an array of them; `player_queues/items(queue_id, limit, offset)`; `player_queues/seek(queue_id, position)`; `player_queues/transfer(source_queue_id, target_queue_id, auto_play)`; `player_queues/get_active_queue(player_id)` returns a `PlayerQueue`; `music/search(search_query, media_types, limit, library_only, providers, user)`; `music/<type>/library_items(favorite, search, limit, offset, order_by, provider, ...)` for artists, albums, tracks, playlists, radios; `music/recently_played_items(limit, media_types, ...)`; `music/browse`, `music/item_by_uri(uri)`, `music/favorites/add_item|remove_item`. Repeat: `off|one|all`. `QueueOption`: `play, replace, next, replace_next, add`.
- **Player fields** (all verified in schema): `player_id, name, type, available, powered, playback_state, elapsed_time(+_last_updated), volume_level, volume_muted, group_members, static_group_members, can_group_with, synced_to, active_group, active_source, current_media{title, artist, album, image_url, duration, queue_item_id...}, enabled, hide_in_ui, private, group_volume, supported_features, icon, device_info`. `PlayerQueue`: `queue_id, active, display_name, state, current_index, current_item, next_item, shuffle_enabled, repeat_mode, elapsed_time, items(count)`. `QueueItem`: `queue_item_id, name, duration, media_item, image{path, provider, remotely_accessible, proxy_id}, index, available`.
- **Images**: `MediaItemImage` has `proxy_id`, and `PlayerMedia.image_url` is a ready URL. The `/imageproxy` route is not in the OpenAPI document; its exact form must be confirmed from the authenticated samples (or the python client source).
- **Still unverified**: websocket result field names for login (`access_token` vs `token`), event payloads, image URL format, whether the Home Assistant add-on proxy needs the token on the `/ws` handshake. Run the sample script.
